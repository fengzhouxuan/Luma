## AOC 桌面验收

显示器工作区为 `(-1920, 0)–(0, 1032)`，缩放 100%。Luma 在 `(-1446, 264)` 测试 900×640 和 640×420；专用测试窗口均在 AOC。

- 点击正在运行的应用：显示两个窗口，并区分“切换窗口”和“恢复并切换”。
- 选择最小化的 B 窗口：恢复到 AOC 上原位置，获得焦点，Luma 收起。
- 列表打开后关闭 B 窗口，再选择旧项目：显示“窗口已关闭或发生变化，请刷新窗口列表”，保留面板；刷新后仅显示 A 窗口。
- `Alt+5` 固定栏快捷键、应用搜索后 Enter：进入相同窗口选择流程。
- 刷新后按 Esc：只取消选择，Luma 主窗口继续可见；已修复全局键盘监听遗漏新面板状态的问题。
- `Shift+Enter`：绕过选择直接再次启动，新增测试进程；普通选择面板中的“再次启动应用”也新增实例。
- 没有现有窗口时 `Alt+5`：直接正常启动测试程序，无多余选择。
- 隔离的 `Code.exe` 参数接收测试程序：识别出独立窗口，不混入同名入口以外的其他 EXE；“新开窗口”传入 `--new-window`，原测试窗口仍保留。
- 系统 MSIX 记事本：通过应用身份识别现有窗口，展示选择面板；测试取消后保留用户现有文档与窗口。
- 640×420 下窗口列表、关闭、刷新和再次启动/新开窗口按钮完整可用，无重叠。

## 边界与交付

- 本机没有安装 VS Code；其真实多开行为未在本机验证。参数来自 VS Code 官方 CLI 文档，参数传递及界面流程已用隔离测试程序验证。仅无参数 Code / Code Insiders 入口启用该选项。
- 其他软件保留原快捷方式、启动参数和工作目录，明确标记“再次启动”；软件自身可能使用单实例。带参数的同一程序会提示窗口可能属于不同配置，不自动选中或切换某个配置。
- 系统拒绝前台切换时保留错误提示；不注入按键强抢焦点。经典 UWP 宿主分支已实现，未在本机建立专用宿主样本验证。
- 窗口标题不进入日志或配置，窗口令牌在内存中最多保存 256 项、5 分钟有效，切换前重新校验。
- 本机安装 1.11.0；测试入口、测试固定项与测试使用记录清理，恢复原窗口尺寸和 AOC 位置偏好。用户配置保留，代码未推送。
- 包含测试临时文件删除的收尾命令被自动审批拦截，仅返回“blocked by policy”；未重试删除。测试进程关闭、应用配置恢复另行完成。`%TEMP%\luma-running-window-qa-1.11.0` 中的源文件、两个测试 EXE 和验收前配置副本保留。
